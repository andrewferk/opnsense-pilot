# The project keeps the name "OPNsense Pilot", asks Deciso for permission before any publication, and renames to "FW Pilot" if refused

OPNsense® is a registered trademark of Deciso B.V. Its [trademark policy](https://opnsense.org/legal-guidelines/) permits using the name "to promote OPNsense based products or services" and "to promote or serve OPNsense or related projects and their communities", but says: "You must request our permission to use derivatives of the name and/or logo at project@opnsense.org prior to any use of the derivative name and/or logo, and we may grant or withhold permission ... in our sole discretion." The policy does not define "derivative". We read a product name that contains the mark ("OPNsense Pilot", `opnsense_pilot`, `opnsense-pilot`) as one, so the name is Deciso's to approve. The 22 PyPI distributions already carrying "opnsense" in their names show tolerance, not consent.

We decided to **keep the name everywhere for now** (project title, repository, Python package, CLI), **request permission by email from the owner's own address no later than the start of release preparation for the first public release**, and **publish or promote nothing under the name until permission is granted in writing**. Silence is a refusal: one follow-up after 30 days, and if there is still no reply when the release is otherwise ready, the project ships under the fallback name. The fallback is **"FW Pilot"** (`fwpilot` on PyPI, import package `fwpilot`, CLI `fwpilot`), always described as "FW Pilot for OPNsense", which is the descriptive use the policy permits. We rejected splitting the names now (a descriptive title with the mark over a mark-free package name) because it adds a permanent vocabulary wart to hedge a refusal that would force a repository and title rename anyway. We rejected relying on the disclaimer alone because "sole discretion" leaves no room to argue nominative use with the mark owner.

## Consequences

- **The gate.** No PyPI upload, container image, public README pitch, blog post, forum post, or social post uses the name before permission arrives. Development, planning, and the public repository under its current name continue meanwhile; the repository is not a promotion.
- **Lead time.** Because silence only becomes a refusal 30 days after a follow-up, the v1 plan schedules the email at the start of release preparation, not on release day. Sending it earlier is allowed and cheaper. The owner sends it; agents draft it and record the reply on [map ticket #23](https://github.com/andrewferk/opnsense-pilot/issues/23).
- **The rename, if it happens.** Repository, `CONTEXT.md`, package, CLI, distribution name, and this ADR (superseded, not edited) all change together in one release. Nothing else in the design depends on the name.
- **Non-affiliation wording** names Deciso B.V. as the mark owner: "OPNsense® is a registered trademark of Deciso B.V. OPNsense Pilot is an independent project, not affiliated with or endorsed by the OPNsense project or Deciso B.V." It appears in `THIRD-PARTY-NOTICES.md`, near the top of the README once one exists, in the PyPI long description, and in the CLI's version or about output. Never claim or imply that the project represents OPNsense.
- **No logo, ever.** The policy ties logo use to permission and a link to opnsense.org, and the docs repository states that logos are not licensed. The project uses no OPNsense logo or derived mark in any artifact, site, or README badge.
- **Reserving the PyPI name** waits for permission; an unused reservation under the mark is itself a use.
- This is an engineering reading of the policy, not legal advice. Policy text read on 2026-09-22 at <https://opnsense.org/legal-guidelines/> and <https://docs.opnsense.org/legal.html>; background in the [upstream licensing research](https://github.com/andrewferk/opnsense-pilot/blob/research/upstream-licenses-and-redistribution/docs/research/upstream-licenses-and-redistribution.md).
